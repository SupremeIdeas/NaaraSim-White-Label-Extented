# Provider endpoint audit against published docs, 2026-10-18

Method: each client was compared with the provider's own published reference (OpenAPI where public) and, where we hold a key, a read-only live call. Keys that are not supplied yet are marked. "Verified" means the request/response shape matches the docs and is covered by `tests/Feature/EsimProviderDocsConformanceTest.php` (or an earlier test named below).

| Provider | Docs source | Result | What changed / what to confirm with keys |
|---|---|---|---|
| Zendit eSIM + gifts | developers.zendit.io (OpenAPI 1.0.13, parsed) | Verified | Offers, purchase, status, plans, refund, qrcode paths all match. FIXED: purchases are asynchronous (ACCEPTED/PENDING/IN_PROGRESS to DONE/FAILED; `confirmation` only on DONE): the client now waits briefly, throws on FAILED (money layer refunds / fails over) and returns an in-flight purchase as `pending` instead of pretending it has an ICCID. Gift FIXED offers no longer send `value`. |
| Zendit voice / SMS eSIM | same spec + live catalogue (5,394 offers) | Not available on our account | The API has `voiceMinutes`, `voiceUnlimited`, `smsNumber`, `smsUnlimited`, but every live offer is data-only (brand "eSIM", subTypes Standard/Fast/Faster/Fastest/Premium, zero voice/SMS). Ask your Zendit account manager to enable voice/SMS eSIM offers; the sync already maps them to Naara Connect the moment they appear. |
| Gigs | developers.gigs.com (markdown reference) | Corrected, key not supplied | Base is `https://api.gigs.com` (we had `/v1`); list endpoints page by cursor with `limit` 0-200 (default 10); a user must be created first; `POST /subscriptions {user, plan, sim:"auto"}`; the SIM is provisioned asynchronously then `GET /sims/{sim}/credentials` gives the activation code/QR; usage via `/usageBalances`; revoke via `/subscriptions/{id}/end`. Plans map voice only when `allowances.voiceSeconds` is non-zero; plans needing an address, or priced in a non-USD currency, are skipped. Confirm with the sandbox: the plan `validity` shape and each plan's `requirements`. |
| 1GLOBAL | docs.connect.1global.com (v1 spec parsed). The newer V3 reference is a JavaScript app that cannot be read without a browser or partner login | Corrected to the documented spec, key not supplied | Base `https://services.truphone.com/connect-api`, Keycloak client-credentials token at `services.truphone.com/auth/realms/tru-staff/...`, `/v1/products`, `/v1/orders` (NEW_ESIM / TOPUP), `/v1/sim/{iccid}`. The documented product has no voice field, so products are stored as data plans. You will likely be onboarded on V3: when you get partner access, compare the V3 reference and adjust `base_url` / `token_url` (both are env settings). |
| Monty Mobile messaging (SMS) | montymobile.com/messaging-api-doc | Verified from docs, no live call | Built earlier (send-only SMS gateway). Needs the Tenant ID, a sender ID and a whitelisted server IP. |
| Monty Mobile eSIM (RSP) | none public (partner portal only; third-party listings say its plans are data-only) | Cannot be verified | The host we had (rsp.montymobile.com) does not exist. It now stays off until `MONTYMOBILE_BASE_URL` is set from Monty's onboarding pack, and it can no longer switch Naara Connect on by itself. |
| eSIM Go | docs.esim-go.com v2.5 + live key | Verified | Catalogue paging, organisation, order shape and `/esims/assignments` all exist in the v2.5 docs. Still to watch: the first funded order. |
| Airalo | developers.partners.airalo.com | Matches the documented `/v2` token, packages, orders (multipart), sims usage | No credentials supplied; first sandbox order will confirm. |
| Quibity | live key, earlier session | Verified | Key is a live key: set `QUIBITY_SANDBOX=false`. |
| Bitrefill | live key | Fixed | Bearer token, `start` paging, live field names. |
| Zendit gift offers | live key | Fixed | Logos come from `brandLogo`; offers are grouped one card per brand and country. |
